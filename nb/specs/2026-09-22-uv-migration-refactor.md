# py-jsrpc 迁移 uv 并深度重构为 src 包

## 问题与目标

项目目前用裸 `requirements.txt` 管依赖（缺 `requests`），代码为 Python 3.7 时代的根目录平铺脚本，使用已被新版 websockets 移除的旧式双参 handler 签名，无法在受管环境下直接安装运行；且没有任何自动化测试，改动无回归保障。

完成后：项目由 uv 管理（单一依赖事实源），`uv sync` 一键装齐运行与开发依赖；`uv run jsrpc-server` 单进程拉起 HTTP + WS 双服务；代码为带类型注解的 src 包；对外的 RPC 协议（js 客户端注册报文、`/send` 接口、回传格式）保持不变；端到端与单元测试可重复运行且全绿。

## 范围

- uv 项目化：项目元数据、运行依赖（sanic、websockets、loguru）与开发依赖（pytest、pytest-asyncio、httpx）全部声明化，生成锁文件与解释器钉版；删除 `requirements.txt`。
- 深度重构为 src 包结构：配置、连接注册表、WS 服务、HTTP 服务、进程入口分模块；全量类型注解（现代语法）。
- websockets 适配新版 asyncio 实现（单参 handler、从请求对象取路径与查询参数）。
- 控制台入口命令 `jsrpc-server`，单进程同时运行 HTTP 与 WS 服务（保持现状模型）。
- host/port 配置化：环境变量覆盖，默认值与现状一致（HTTP 127.0.0.1:5000，WS 127.0.0.1:6789）。
- 失败路径结构化：`/send` 缺 `group` 参数、group 无可用 js 客户端——现状分别抛 KeyError、IndexError 导致 500（仅连接失效的边缘场景表现为调用方无限挂起）——统一改为立即返回结构化错误 JSON。此为有意的行为改进（500/挂起 → 明确错误），已列入验收。
- 自动化测试：注册表单元测试 + 全链路端到端测试（真实启动服务、模拟 js 客户端、走 HTTP 调用）。
- 清理：删除手动计时脚本；js 客户端文件原样移入包内 `static/`；README 改写为 uv 工作流。

## 非目标

- 不修改 js 客户端文件内容（浏览器侧注入方式与协议不变）。
- 不引入多进程/分布式、认证鉴权、TLS。
- 不改变单事件循环、进程内内存注册表的运行模型。
- 不发布到 PyPI。
- 不改 `/send` 成功路径与注册/回传报文的任何字段。

## 验收场景

1. 干净检出后执行 `uv sync` → 成功创建虚拟环境并安装全部运行与开发依赖；仓库中不再存在 requirements 文本清单。
2. 执行 `uv run jsrpc-server` → 单进程同时监听 HTTP 127.0.0.1:5000 与 WS 127.0.0.1:6789，日志可见两个服务就绪；设置环境变量（HTTP/WS 各 host、port 四项）后重启 → 在覆盖后的地址监听。
3. 端到端 RPC 往返：模拟 js 客户端按协议连接 `ws://…/register?group=g&clientId=c1`；HTTP `GET /send?group=g&action=clientTime&x=1` → 客户端收到转发报文，含 `action=clientTime`、`x=1` 与 `__uuid_seq__`；回传 `{"status":0,"data":…,"__uuid_seq__":…}` 后，HTTP 响应 JSON 含 `status=0` 与 `data` 字段。
4. 客户端动作不存在：模拟客户端对未注册 action 按协议回 `status=-1` 报文 → HTTP 响应原样携带 `status=-1` 与 `message`。
5. group 无已注册 js 客户端时调用 `/send?group=nobody&action=x` → 立即（不挂起）返回含 `error` 键的 JSON，HTTP 状态码非 5xx。
6. `/send` 缺 `group` 参数 → 返回含 `error` 键的 JSON，非 500。
7. 执行 `uv run pytest` → 单元测试与端到端测试全部通过。
8. js 客户端文件存在于包内且内容与迁移前逐字节一致；README 仅描述 uv 安装、启动、测试工作流。

## 设计决策

- uv 为唯一依赖事实源；`requests` 不再是依赖（原用途是手动脚本，已被 pytest + httpx 取代，httpx 仅在开发依赖组）。
- Python 下限 `>=3.10`（现代类型语法）；实际解释器以本机 uv 解析结果为准，若 sanic 等依赖不兼容本机最新解释器（3.14），用解释器钉版文件固定可用版本——属执行期事实核验，不改变本决策。
- websockets 用新版 asyncio 实现的单参 handler；路径与查询参数从连接请求对象解析（查询解析用标准库 `parse_qs`，行为与现有正则等价且对边界字符更稳）。
- WS 监听地址统一为 `127.0.0.1`（现状一处写 `localhost`、一处写 `127.0.0.1`，行为在本机等价，统一之）。
- 进程入口保持现状模型：先挂 WS 服务后台任务，再运行 HTTP 框架，单进程单事件循环。
- 注册表独立成模块：封装注册、注销、按 group 随机选取；group 为空或客户端离线时返回"不可用"信号，由 WS 层翻译成结构化错误报文——消除现状的 KeyError/IndexError 与调用方挂起。
- 失败路径统一约定：HTTP 入口对缺参与无客户端两种情况返回 `{"error": "<原因>"}`；不引入错误码体系。
- 端到端测试以子进程方式启动入口命令，用环境变量注入随机空闲端口，避免端口冲突；模拟客户端报文严格按现有 js 客户端源码的线上格式构造，作为协议不变的回归证明。

## Rulings

- 2026-09-22/切片3：`workers=1` 在 Sanic 25 仍走多进程管理器、子进程按名重导入 app 失败——改用 `single_process=True`。依据：与"单进程单事件循环"的批准模型一致，且为迁移前实际行为。代价：若判断错误需回到 add_task+进程内 run 的旧形态，回滚一行。
- 2026-09-22/切片3：HTTP 层加 30s 兜底超时（模块常量，未扩环境变量面），保证"已注册但连接失效"边缘场景不无限挂起。依据：验收场景 5 要求不挂起。代价：慢于 30s 的合法 js 回包会被判超时。
- 2026-09-22/切片3：WS 层对非 JSON 帧、非对象帧、孤儿 seq 由现状"异常杀死连接"改为"日志告警丢弃"；未知路径以 4001+原因关闭（现状静默持有）。依据：失败路径结构化条款；均不在协议不变范围内。代价：若外部有依赖异常断连副作用的用法会受影响（仓库内无此用法）。
- 2026-09-22/复审：webclient 回传目标（apiclient）连接已断时补 try/except ConnectionClosed（与反向路径对称，修复与模块自述矛盾的漏网点）；注册表注销改为按连接身份校验，防固定 clientId 快速重连时旧连接迟到注销误删新注册（现状同型缺陷，新模块内修复，未新增协议面）；e2e 子进程改起真实 jsrpc-server 入口脚本回归 [project.scripts] 声明。依据：独立复审 Findings（均 Medium/Low）；失败路径与协议不变边界均未突破。代价：身份校验若判断错误会造成注册残留（有 e2e 与单测兜底）。
- 2026-09-22/完成后（commit 3444ae6，Quick 契约经用户批准）：本 spec 验收场景 2 的 WS 默认监听由 `127.0.0.1` 改为 `localhost`（v4+v6 双栈；浏览器对 `ws://localhost` 优先尝试 `::1`，单栈 v4 绑定致浏览器静默连不上、服务端零日志，验收当时的"本机等价"断言被浏览器场景证伪）。默认值现权威见 `AGENTS.md` 项目陷阱章。依据：Quick 契约卡批准 + 双栈 LISTENING 与 `::1` 注册实测。代价：无。
